# 接入配置

由使用者填写以下项目，或提供内容等价的目标库说明。优先复用当次任务已经提供的信息。只有涉及的操作确实需要某项时，才补问。

| 项目 | 填写内容 |
| --- | --- |
| 知识库与范围 | 名称、入口、可用的检索范围，以及本批材料适用的主题。 |
| 现行规则 | 规则的链接或可靠位置。匿名、改稿、审核和定位格式从对应规则读取。 |
| 库结构 | 单库、分库或目录式。填写知识正文、出处证据、原件档案分别放在哪里。 |
| 字段及关系映射 | 可检索标题、正文、定位、原件入口、审核状态、父子或关联条目用目标库的哪些字段、标题或链接表示。 |
| 状态映射 | 草拟、待确认、获批、生效及仅索引分别怎么表达。没有状态字段时注明等价的目录、标记或审核记录。 |
| 确认权限 | 有权批准的角色或身份，以及能明确对应提案版本与条目范围的批准方式。 |
| 当次动作 | 用户本次请求的是读、准备稿、提交草稿、合入还是某项明确批准的额外操作。 |

## 接入时核对

- 确认可用字段、链接和位置与目标当前状态一致。记录尚未建立的可选位置，在草稿里保留映射。
- 根据任务核对实际读写能力。配置描述权限约定，批准记录说明本次授权。两者都与任务相符时再执行对应写入。
- 每条知识至少能链接或定位到来源。如果库已分层，走完整的「知识 → 证据 → 原件」关系。不创建重复原件入口。

## 虚构示例

| 项目 | 示例甲 · 单库 | 示例乙 · 分库 |
| --- | --- | --- |
| 入口 | 示例甲／交接卡片 | 示例乙／维护手册总目录 |
| 规则位置 | 《卡片编写与确认办法》 | 《维护条目的现行规则》 |
| 结构和定位 | 同一张卡片写做法和「原件入口」，出处定位写标题和段落 | 操作条目关联证据条目，证据条目再指向原件档案 |
| 主要字段 | 「工作问题」「做法」「原件入口」 | 「维护事项」「操作说明」「引用资料」 |
| 状态 | 「流转」字段使用「预备」「会签」「启用」，目录条目用「仅索引」标识 | 用「审阅稿」目录和「现行」目录表达流程，批准范围写在审阅记录 |
| 确认权限 | 值班主管在批准记录中明确给出提案版本和卡片编号 | 手册维护人批准具体提案和拟改段落 |

目录式示例可用「现行方法目录」存知识页、「资料」存出处页、「原件」存原件路径或链接，审核方式沿用该库规则。以上名称、数据和规则均为虚构。

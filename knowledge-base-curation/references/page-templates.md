# 页面与记录模板

选择与目标库匹配的字段、标题和关系。带条件的做法把条件放在同一条或紧邻位置。按实际内容保留段落。使用目标库规定的出处格式与匿名方式。

## 知识条目

| 项目 | 填什么 |
| --- | --- |
| 标题 | 能独立检索的操作或实际问题。 |
| 核心做法 | 一至两句回答具体怎么判断或采取行动。 |
| 使用条件 | 说明什么时候用。更详细的门槛、例外和案例前提放正文。 |
| 判断和步骤 | 标清原文规定的先后、讲解排列、并列因素或案例的顺序。 |
| 具体做法与案例 | 保留必要语境。记录案例条件、采取的动作、可核实的结果及来源评价。 |
| 已知缺口与出处 | 说明核实过的范围，附来源身份与位置。 |
| 字段与状态 | 用目标库映射，字段和正文的含义一致。历史与待审建议分开。 |

## 证据资料与原件

| 记录 | 可用模板 |
| --- | --- |
| 证据资料 | 可检索标题、原件身份、准确定位、必要短引或整理说明、上下文、案例范围、关联条目。混合引文与整理说明时分段。 |
| 原件档案 | 依目标规则登记标题、载体、版本或日期和访问入口。已有入口时复用，保留原件。 |
| 仅索引 | 真实标题或目录位置、原件入口（已知时）、可读范围、正文待补状态。收到正文后按稳定标识找到原记录再更新。 |

## 修订提案

把一项可以单独批准的改动写成一行。需要联动的字段与正文可放在同一项，以便一次确认。

| 提案号与版本 | 条目与具体位置 | 当前内容或状态 | 拟改内容和状态 | 原因与新证据 | 审核备注 |
| --- | --- | --- | --- | --- | --- |
| 批次标识／稿次／项号 | 页面或记录标识＋字段或段落 | 说明可核对的基线 | 写出确切改动 | 记录原件和定位 | 注明是否影响相关条目 |

## 虚构正反例

原材料《值班交接说明》修订 2 的「短班交接」第 2 段写：「短班交接时，可先确认设备状态；库存和人员名单按当天表格逐项核对。」

- **正例**。标题写「短班怎么交接」。做法写「短班交接可先确认设备状态。库存和人员名单按当天表格逐项核对」。范围保留「短班」，出处标修订 2 与段落位置。「可先」保留为建议性的动作。
- **反例**。写成「所有交接一律先查设备、再查库存、最后查人」。这扩大了适用范围，把选择性动作写成必做，也添加了库存和人员的先后。

同一正例放在单库时，可以在条目正文旁设「出处」和「原件链接」；放在分库时，知识条目连证据页、证据页连原件；放在目录式库时，用相对链接或库支持的稳定链接实现同样回查。

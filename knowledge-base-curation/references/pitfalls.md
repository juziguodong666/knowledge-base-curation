# 常见错误与改法

以下数据和名称均为虚构。按改法核对现有证据，并遵循目标库规则。

| 虚构反例 | 正确处理 | 在哪一步发现 |
| --- | --- | --- |
| 手册列「库存、设备、人员」，条目写成固定的三步。 | 核对原文是否规定先后。若只是并列检查，保留并列与要求逐项检查的条件。 | 拆因素、自查 |
| 「如果只做一件事，你会先做什么？」被写成「每次只能做一件事」。 | 保留假设和问句语气。可解释它引导聚焦，清楚标注是整理说明。 | 写页、自查 |
| 低温运输单个案例采用二次复核，写成所有运输都必须二次复核。 | 把条件、实际做法和可核实结果留在该案例。通用做法另找证据。 | 拆因素、写页 |
| 「它需要复查」前文同时提到了表格和设备，条目径直写「设备需复查」。 | 回读前后文、所属章节和图例。仍不能确认对象时列为待核实，暂缓依赖它的结论。 | 拆因素、自查 |
| 未指定的便笺写「每次都罚扣」，条目用它补充正式材料。 | 对照来源范围。只写指定材料支持的信息，缺乏依据的罚扣要求留空或待核实。 | 建档、写页、自查 |
| 原文只说回访过两次，概括却加上「因此成交」。 | 逐条回查概括中的结论，保留有依据的内容并标为整理概括。推断或建议另行标注。 | 写页、自查 |
| 将「必要时检查」改成「每次都检查」，仍放在引号内。 | 对照源文逐字核对引文和数字。需压缩时移出引号，以有出处的概括表达。 | 自查 |
| 案例里说经过 12 次检查，条目把 12 写成小时数。 | 回查单位、范围、对象与统计口径。对图表还要核对图例和脚注。 | 写页、自查 |
| 已匿名正文，标题、文件显示名或链接文字仍暴露身份。 | 按目标规则核对所有拟写入位置。保护原件，按规则处理知识库中的展示内容。 | 自查 |
| 字段写所有情况适用，正文只说夜班适用。 | 用同一范围写字段和正文，在正文展开例外。 | 自查、读回审计 |
| 修订记录里的旧做法被当成现行规则引用。 | 从生效内容取答案，将历史、待审提案和现行内容明确区分。 | 查重定位、覆盖审计 |
| 收到的文件只有目录，却从标题写出了操作步骤。 | 登记为索引或占位，正文待补。收到正文后补回同一记录。 | 建档、查重定位 |
| 转发「主管同意了」就改状态，或把只批准的两项扩大到全批。 | 核对可确认的本人答复、提案版本和批准项，保留其余项待处理。 | 提交、合入 |
| 写入接口超时后按旧清单全量再建。 | 按记录标识、来源版本和拟改结果先读回，再补缺项。 | 合入、覆盖审计 |
